loopd · the loop, running

You steer.
They build.
Two gates stay yours.

loopd is a Claude Code plugin that runs a small team of AI agents on your repositories. You describe the work. A project-manager agent breaks it into tasks. Engineer agents build them in the background, open pull requests and get reviewed. You promote, and you merge; everything else reaches you as a result or a question.

the loop

Four steps. Two of them are yours.

Blue is the machine's — agents, code, refs, running state. Pink is yours — every pink pixel is a decision waiting. Nothing is dispatched until you promote, and nothing reaches main until you merge.

flow retry exit to main
  1. 01 · agents

    /loopd:new-project

    One sentence is enough. You and the main session scaffold phases and draft tasks; the project-manager agent then refines each one: acceptance criteria, and the questions only you can answer.

  2. 02 · gate 1

    You promote draft → ready

    The PM refines and critiques a draft but never sets ready. Nothing is dispatched until you promote.

  3. 03 · agents

    /loopd:dispatch

    One tick at a time. Each ready task gets its own worktree and branch; an engineer agent builds it, reviews its own diff and opens a PR with the criteria as a ✓/✗ table.

  4. 04 · gate 2

    You merge the PR

    An independent reviewer with fresh context checks it first. One ✗ in the criteria table blocks the merge — however green CI is. Agents never merge.

The retry edge · two rounds, then you decide

Review sends the PR back to its agent. Round 1: the reviewer reports, the agent fixes and replies once. Round 2: the reviewer checks only what it raised. There is no round 3 — whatever is still open comes to you in one short block. docs/autonomy.md

the crew

They build in the background. You get the decisions.

Agents · blue

Refine, build in their own worktrees, open PRs, review with fresh context — in the background. Results and questions bubble up; every step does not.

You · pink

Two gates, by default: promote draft → ready, and merge. Anything waiting on you lands in AWAITING.md and on the session banner.

install

About ten minutes to your first loop.

Needs Claude Code, git, gh and bash. The plugin installs once per machine; each group of repositories gets its own bundle — a small git repo that holds the state of the work, never application code.

   ▄▄▄▄
◀━▐    ▌   loopd — the loop, running
  ▝▄▄▄▄▘# once per machine
/plugin marketplace add cbmono/loopd
/plugin install loopd@loopd
# or core + autonomy companion + mods, in one
/plugin install loopd-all@loopd
# or add one mod on its own
/plugin install loopd-mod-usage@loopd

# once per group of repositories
/loopd:init ~/workspace/<group>/_loopd-<group>

# then, every time
/loopd:new-project add rate limiting to the public API
you promote draft → ready
/loop 10m /loopd:dispatch
you merge the PR

The full install guide covers configuring the bundle, giving it a remote and sharing it between two people.

safety rails

None of them is decoration.

Independent review

Every PR is cleared by a reviewer with fresh context — never the implementing agent's own report.

Exit 0 is the only clearance

Missing, pending, skipped and unreadable checks all refuse. A green check from a reviewer that declined to review is not verification.

Done means a PR exists

An agent's "done" is not evidence. The dispatch check asks whether the status moved and the PR resolves — and only reports.

One tick at a time

A lock refuses a second orchestrator. Stale or unattributable means ask the human — never delete, never adopt.

Never deletes on a guess

The worktree pruner only reports. A worktree goes when its task is done with every PR merged, or when you say yes to /loopd:prune-wt. The bundle repair is report-only by default.

The gates can be delegated

Only through the separate loopd-yolo companion plugin, which loopd-all includes; each project stays gated until it opts in. Uninstall it and every project is gated again, with no other edits.
