# loopd 3.14.0

**Review rounds are configuration, QA takes over when CodeRabbit can't, and the last fix merges without a re-review.**
How many CodeRabbit and QA rounds a PR gets is now set per instance, a real CodeRabbit refusal
dispatches one adversarial QA round in gated and yolo alike, and after the last round a small fix
merges on green instead of waiting for a review that never comes.

**10 merged pull requests since 3.13.0** (#435–#444).

| | |
|---|---|
| **Upgrading** | `/plugin update` (or `claude plugin update loopd-all`), restart Claude Code, then `/loopd:init` in each bundle: the seed config gained `coderabbitRounds`, `qaRounds` and `reviewFixMaxLines` (#438, #443), and init reports any key your config lacks |
| **Check it** | `scripts/review-next.sh <pr> --repo <o>/<n>` prints the loop's next review move for a PR (`dispatch-qa`, `request-review`, `implementer-round`, `merge-path`, `hold`…); a new agent PR comment ends with `— <ownerGithubUser>-<role>` |
| **Breaking** | `mergeAtReviewCap` is retired and no longer read: `coderabbitRounds` plus the merge after the last round replace it (#438, #443). The two-round cap is gone; the default is now **one** CodeRabbit round and **one** QA round. New installs seed `qa-reviewer` at the `apex` tier (#439); an existing config is never rewritten. Agents may no longer write, move or delete credential stores outside their worktree (#440) |
| **Companions** | `loopd-yolo` 3.1.0 → 3.2.0, because its shipped `AUTONOMY.md` changed since its version was set |

## Review rounds and the QA fallback

- **`coderabbitRounds` and `qaRounds`** (default 1 each) cap each reviewer separately; `review-rounds.sh --for coderabbit|qa` counts them apart, and one commit reviewed by both is one round, not two (#438).
- **A real CodeRabbit refusal dispatches one `loopd:qa-reviewer` round, immediately, in gated and yolo.** A rate limit, a used-up allowance or no credits counts; the "currently processing" placeholder, exit 8 "review skipped" and no reviewer signal hold and spend nothing. `review-next.sh` makes the call (#441).
- **QA rounds continue only while the previous round found bugs**, up to `qaRounds` (#441).
- **A same-login QA verdict counts only against the tick's own dispatch record** for that PR at that head (`qa-dispatch.sh`), so an implementer cannot clear its own PR with a trailer (#441).
- **The QA reviewer defaults to the `apex` tier** (fable) (#439), and **at apex it adjudicates the cheap `/code-review low` itself** instead of escalating to the `code-architect` + `deep-bug-scan` pair; below apex nothing changes (#444).

## Merge after the last round

- **No re-review after the last round's fix**, when the head descends from the last reviewed commit and changes at least one and at most `reviewFixMaxLines` lines (default 300) since it; over the cap the loop holds for the human (#443).
- **After the last round, open reviewer threads and the last QA round's FAIL rows block nothing** — the fix is taken as their answer (#443).
- **yolo merges once every required check except CodeRabbit's is green**; gated surfaces the PR for the human, unchanged. PRs touching the gate's own files still never self-merge (#443).
- **`qaRounds: 0`** with a CodeRabbit limit refusal, or `0`/`0`, merges on green under yolo with no review at all — an explicit opt-in, documented in `AUTONOMY.md` (#443).

## Agents, hooks and the loop

- **Every agent PR comment and review ends with a role signature** `— <ownerGithubUser>-<role>`; a label only, no gate reads it (#437).
- **`deny-destructive.sh` refuses writes, moves and deletes on credential stores** (`~/.ssh`, `~/.aws`, `~/.config/gh`, `*.pem`, `id_rsa*`, `*credentials*`) outside the task's worktree, through redirects, substitutions and `mv` sources (#440).
- **The idle probe counts a dispatchable `ready` task and a draft awaiting critique triage as work**, so a task the previous tick promoted is dispatched next tick instead of waiting for an outside change; a blocked task stays idle (#442).
- **`do-not-repeat.sh` reads block-form lists and rereads every write** (#435).
- **The Service-doc match accepts a repo however its `repo:` is spelled** (#436).

## Known issues

- A QA agent dispatched from the main session shares that session's scratchpad; give its draft files a unique prefix.
- `tick-delta.sh`: with no `claude` on PATH, a dispatchable task reads as a delta every tick while the fingerprint keeps its fast path.
