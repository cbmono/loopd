# loopd 3.6.0

**The tick looks after its own background sessions, and a person who never runs a tick
can answer a question and start a project from the pane.** Role sessions are resumed by
their full id, stopped by the tick once their round is recorded, and spawned under a
grant Claude Code no longer warns about. Open questions now carry options and depths,
and `/loopd:answer` and the pane's simple mode take them one press at a time.

## Background sessions: resume, stop, report

- **A session is resumed by its full id** (#373, #377). `--resume <short id>` parks on the
  picker (measured on 2.1.295); step 3 now records the full 36-character id at spawn, and
  `agent-sessions.sh full` maps either spelling, so older tasks with a short id still
  resolve. The next tick stops a resume stalled on the picker and runs one fresh round; a
  second stall escalates. `claude stop`/`logs` take the short id, `--resume` the full one.
- **The tick stops a `blocked` session whose round is recorded** (#379), and resumes it
  only when a round is owed. With nothing recorded the human gate is unchanged. The stop
  needs `Bash(claude stop *)`, written on the same yes as the spawn grant.
- **A resume carries no spawn flags** (#383) and reads the session id off the CLI's
  stdout. A `done` task's own idle session is stopped before its worktree is reclaimed; a
  reclaim refused only by that session is a silent retry, not a human item. On the first
  tick, older `done` tasks with a worktree on disk and no `worktree retained:` note get one
  reclaim each, under the same guards.
- **A `--bg` round ends with a report and one status line** (#380); every ask for the
  human goes to the task's `open_questions`. Nothing predicts the CLI's verdict.

## The spawn grant: one rule per role (#385)

The tick's spawn puts the brief last, and `/loopd:init` grants it with one rule per role
(`software-engineer`, `devops-engineer`, `qa-reviewer`, `cataloguer`) plus a flag-free
resume rule, each with a single trailing `*`. Claude Code stops warning at startup, and
an inserted flag no longer matches. The old `Bash(claude --bg * --agent loopd:*
--permission-mode auto --add-dir *)` is named and replaced on the same yes. A bundle path
that needs shell quoting gets no spawn rule, only the resume and stop rules. Measured on
2.1.302; the table is in `docs/operations.md`.

## Open questions with options, and `/loopd:answer`

- **An open `Q<n>:` question carries a `### Q<n>` block** under `## Question details`
  (#375): a recommendation, options and three depths of context. Refine writes it;
  `validate-bundle.sh` warns when it is missing (`--strict` fails). Frontmatter and its
  six readers are unchanged.
- **`/loopd:answer <task> [Q<n>] <n | more | text>`** (#376) records an option's text,
  free text, or prints the next stored depth; past the stored depths it asks the model in
  the human's own session, never during a tick. It moves the entry, commits as the human
  and pulls with rebase before pushing; a failed rebase or rejected push stops and never
  forces.

## The pane: simple mode and a New project form

- **`plugin-mod-pane` has a `mode` switch in `/config`** (#378). `simple` draws per-project
  done/total bars, open questions (recommendation first, the other options, a text field,
  More) and blocked tasks as one sentence each, with no agent, tick, PR or session
  vocabulary. Every press runs `/loopd:answer`; operator mode and the published board are
  untouched.
- **The command is `/pane`** (#381): `/board` is loopd's own board skill, so the mod's
  `/board` was refused wherever loopd was installed.
- **A four-field New project form** (#382) — title, what, for whom, done when — runs
  `/loopd:new-project` once. The skill gains `title=`, `need=`, `success_criteria=` and
  `--no-ask`. The mod still writes nothing. The skill commits and does not push, so on a
  two-clone bundle the project stays on the creator's clone until pushed.

## Worktrees

**`/loopd:prune-wt`** (#372), human-only: removes the pruner's `REMOVABLE` set after one
yes, re-checking each path with `reclaim-worktree.sh`'s guards — refused under a held
`.tick-lock`, a live process spares its path, an ignored `.env` spares its worktree, no
`--force`. `prune-worktrees.sh` stays report-only.

## Fixes

- **Skills find `SCHEMA.md` at the resolved schema path** (#347): seven skills' instance
  precondition checked the bundle root only.
- **An expected-sha lease is written braced** (#384):
  `--force-with-lease="refs/heads/${BRANCH}:${SHA}"`. zsh read `$B:h1` as the `:h`
  modifier and dropped the colon. A harness refuses the unbraced form under `plugin/`.

## Docs

The README (#370), the `docs/*.md` guides (#371) and the landing page (#374) describe
3.3.0–3.5.0 as shipped; the landing page's install block matches the README and five
drifted claims were corrected.

## The release question

*For each hook, gate and script, which assumption has this model generation made
unnecessary?* None. Two assumptions about the **CLI** were found false: that a short
session id resumes a session (it parks on the picker), and that a permission rule with a
`*` in the middle is a narrow grant (Claude Code warns about it, and a flag inserted where
the `*` sits still matches). Both are now pinned by harnesses.
