# loopd 3.3.1

**The upgrade order in 3.3.0 is now enforced instead of asked for.** 3.3.0 renamed the
bundle's state directory and said: migrate each bundle *before* updating the plugin. Three
bundles were updated first, and nothing said so — `/loopd:init` seeded an empty second state
directory beside the real one, and the migration then stopped because its destination
existed. Each was recovered by hand. This release makes that impossible.

**3 merged pull requests since 3.3.0.**

| | |
|---|---|
| **Upgrading** | `/plugin update`, restart Claude Code, `/loopd:init` in each bundle. If a bundle has not been migrated yet, init now **refuses and prints the two commands** instead of stamping; run them, then init again |
| **Check it** | `/loopd:init` on a migrated bundle runs as before; on an unmigrated one it exits 2 with `still keeps its state in .ai-bridge/` and writes nothing |
| **Breaking** | nothing |

## `/loopd:init` refuses a bundle that still keeps its state in `.ai-bridge/` (#349)

The stamp exits 2 **before writing anything** and prints `migrate-bundle.sh` and
`migrate-bundle.sh --apply`. The session banner's notice and `/loopd:welcome check` name the
same condition, including the half-stamped shape where both directories exist — there the
stray new directory has to be moved aside first, because the migration stops while it is
there. A first stamp, a migrated bundle and a directory that is not a bundle are untouched.

## `kb-sync.sh status` no longer says "clean" over uncommitted edits (#350)

It counted commits ahead of the remote and nothing else, so a mount with 865 modified,
uncommitted knowledge documents reported `KB mount is clean and pushed.` It now counts
tracked files with uncommitted changes under the knowledge path, prints the commit command
and exits 1. An **untracked** new document inside `knowledge/` still reads as clean, because
the mount sees every other bundle file as untracked too; that is a separate decision and is
recorded here, not hidden.

## The hooks' plugin root is quoted (#350)

`claude plugin validate --strict` warned nine times that `plugin/hooks/hooks.json` used
`${CLAUDE_PLUGIN_ROOT}` unquoted: a config directory with a space in its path would have
split every hook command, the safety baseline included. Quoted; nothing else in the file
changed. The validator passes.

## The release question

*For each hook, gate and script, which assumption has this model generation made
unnecessary?* None in a patch release. One assumption was found to be false rather than
unnecessary — that an operator reads the upgrade order in a release note before running
the update. The guard replaces the reading.

Evals were not re-run for this release: no agent, skill or command text changed.
