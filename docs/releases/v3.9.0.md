# loopd 3.9.0

**A `yolo` project can opt in to merging a PR at the two-round review cap, and a shared
bundle stops showing one human the other's finished projects.**

## Merge at the review cap (#397)

- **Opt-in, default off.** A new `mergeAtReviewCap` key lets a `yolo` project merge a PR
  at the two-round review cap when the reviewer's last answer at the head is exit 6
  (cleared with remarks). The cap itself is unchanged: two rounds.
- **Recorded, not implied.** The clearance receipt carries `--cap` lines only while the key
  is true, and `required-checks.sh` notes when it accepted the review half at the cap.
- **Off means unchanged.** Without the key every merge decision is exactly as in 3.8.0,
  and a `gated` project is never affected.

## Close rows by owner (#396)

- A close row in `AWAITING.md` now renders only where `task-owner.sh` on the project's
  `project.md` clears it, the same check the continue row already used. On a shared bundle
  each human sees only their own finished projects. A project with an owner on a clone
  with no `ownerGithubUser` shows no close row.

## The release question

*For each hook, gate and script, which assumption has this model generation made
unnecessary?* One, narrowly: that every PR stuck at the review cap needs a human, even on a
project whose owner has delegated merging. #397 retires it only where the owner opts in.
