# loopd 3.11.0

**Simple mode arrives on both boards, and the loop stops stalling on a rate-limited
reviewer.** The web board opens on an inbox and the pane's simple mode becomes one; the idle
probe now sees review activity, and a reviewer's clean result posted as a comment counts.

**5 merged pull requests since 3.10.0.**

| | |
|---|---|
| **Upgrading** | `/plugin update` (or `claude plugin update loopd-all`), restart Claude Code, then `/loopd:init` in each bundle: the seed config gained keys the machinery already read (#402), and init reports any your config lacks |
| **Check it** | `/loopd:board serve` opens on the inbox, with today's board behind Show details; `/loopd:welcome check` no longer calls `mergeAtReviewCap` or `reclaimIgnoreOk` unknown |

## Simple mode

- **The web board opens in simple mode** (#398): an inbox beside a progress rail, filters,
  drawers, keyboard shortcuts and a light theme, with today's board behind Show details. The
  page sends nothing, and its Needs you counts pending approvals, merges and project closes
  as well as questions and stuck tasks.
- **The pane's simple mode is an inbox** (#400): one open question at a time, Later, stuck
  items split by who can fix them, progress in creation order. It adds `answer.sh later` and
  a new `/loopd:unblock <task>`. Every button runs one slash command; the pane still writes
  nothing itself.

## The loop and its reviewer

- **The idle probe sees review activity** (#403). Its per-PR line carries the review count,
  the latest review's id and state, and every commit status's state and description, so a
  COMMENTED review, or a reviewer status that says "rate limited" or "skipped", is a delta.
  An unreadable value reports UNKNOWN, never IDLE.
- **A clean review posted as a comment counts** (#404). `review-clearance.sh` clears a
  reviewer's head marker that is newer than its last review object, when the marker carries
  no refusal text. CodeRabbit's "Action not completed / Review rate limited." reply is still
  a refusal, and a marker from another author or for an older head never clears.

## Config (#402)

- **Every key the machinery reads is seeded**, so `welcome.sh check` knows it; a new
  harness keeps the seed and the readers in step. `normalise-config.sh` keeps a local
  `reclaimIgnoreOk` in the local file instead of dropping it.

## Known issue

- `build-board.sh` writes no page when a snapshot's `awaiting` value is a list or an
  object rather than text. Every writer in this release produces text; a guard is tracked.

## The release question

*For each hook, gate and script, which assumption has this model generation made
unnecessary?* That a reviewer's verdict always arrives as a formal review object. #404
reads the head marker where the review object is missing, and keeps every refusal it had.
