# loopd 3.3.2

**A layout change never edits a knowledge document again.** The 3.3 migration moved a
bundle's state directory and, in the same run, repaired knowledge documents — 865 of them
in one bundle whose `knowledge/` is a mount of a shared company repository, with
`provenance` values derived from the wrong history (the move itself read as a human edit).
They had to be reverted by hand. This release separates the two and fixes the derivation.

**3 merged pull requests since 3.3.1.**

| | |
|---|---|
| **Upgrading** | `/plugin update`, restart Claude Code, `/loopd:init` in each bundle. A bundle not yet migrated: run `migrate-bundle.sh --layout-only`, then `--layout-only --apply` — the directory moves, no document is touched |
| **Check it** | `migrate-bundle.sh --layout-only` on a migrated bundle says so and exits 0; a dry run in a bundle with a knowledge mount lists `knowledge/` once as SKIPPED |
| **Breaking** | nothing |

## `migrate-bundle.sh --layout-only` (#353)

Runs only the two structural steps — the 3.0 layout move and the 3.3 rename — with every
existing refusal, and prints `content: NOT CHECKED`. Its summary never takes the ordinary
`N fixed` shape, so it cannot be mistaken for a clean content pass. The init refusal and the
session banner's notice now recommend it.

**A mounted `knowledge/` is skipped by the content pass in every mode**, reported once:
*lives in a knowledge mount; repair it from that repository, not here.* A mount is another
repository's working tree; this script repairs this bundle's own files. The mount also
could not be read correctly: `git log` inside it resolved to the bundle's repository, which
ignores `knowledge/`, so every mounted document's history was invisible to the derivation.

## The provenance derivation (#354)

- A commit that only deletes or renames the file is not a touch of its content.
- A commit by a non-role author touching more than **50** knowledge documents is a bulk
  move: ignored as a later touch, and if it created the file the author is unknowable.
  Measured bulk commits were 326, 334 and 873 documents; hand-edit sweeps are far below.
- Unknowable history writes **nothing** and is reported as skipped, leaving the validator's
  error standing. It used to write `human (unresolved)`, which reads as a fact. No enum
  value was added; `SCHEMA.md` says the `human` row is then a person's call.

## Handing off a project with work in flight (#352)

An `in-progress` task whose `worktree:`, `branch:` and `session:` live on the old owner's
machine is named by the handoff with its two routes — finish it, or release it and push —
because the new owner's clone can neither observe nor settle that session. Measured on the
first real two-human handoff, 2026-10-05. The skill still changes nothing on the task.

## The release question

*For each hook, gate and script, which assumption has this model generation made
unnecessary?* None. One assumption was found false: that a document's provenance can be
read from whichever repository the script happens to be standing in.

Evals were not re-run: no agent, skill or command text changed except the handoff skill's
prose, which no eval case exercises.
