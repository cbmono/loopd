## `loopd-all` (#363)

A bundle plugin with no components: `loopd`, `loopd-yolo`, `loopd-mod-usage`,
`loopd-mod-pane`, `loopd-mod-signal` as dependencies. Installing it installs all five;
updating it fetches whatever was added since. Disabling a mod disables only the empty
bundle, never `loopd`, which declares no dependencies of its own. `loopd-accounts` and
`loopd-llm` stay out: both are per-machine decisions a person takes on purpose. Measured
in an empty config directory: one install, six plugins listed.

**Found on the way:** disabling `loopd-yolo` in `/plugin` does not switch delegated
autonomy off — `resolve-autonomy.sh` reads what is installed. Uninstall is the off switch.
Stated in the README and pinned; making disable mean off is a follow-up.

## `/loopd:init` does the three things the second human did by hand (#364)

- **A configured knowledge base is mounted, not seeded.** With `knowledge.repo` in the
  config and no mount, the stamp skips the nine `knowledge/` placeholders and runs
  `kb-sync.sh mount` itself. Real content in `knowledge/` is refused as before; a
  placeholder-only folder from an earlier stamp is named with the `rm` to run, never
  removed; an unreachable remote is a `warn` plus the `pull` to run later. A stamp never
  fails on the network.
- **`authorEmail` comes from the `people` map** when the local config lacks it and
  `ownerGithubUser` has an entry — written to the local file only, verified after the
  write, never overwriting a value already there.
- **The spawn grant is asked for.** On a terminal stamp, when the exact auto-mode rule is
  absent: `Write "Bash(claude --bg * --agent loopd:* --permission-mode auto --add-dir *)"
  to .claude/settings.local.json so the tick can start role agents without a prompt?
  [Y/n]`. Three stale shapes are named and removed on the same yes: a bare
  `Bash(claude --bg *)` (far too broad), any `bypassPermissions` spawn rule, any spawn rule
  under a retired agent namespace. `n` prints the rule as before.
- **`docs/onboarding.md`** is the two-command page; the earlier "first hour" page moved to
  `docs/first-hour.md` unchanged.

## `loopd-mod-signal` (#361)

A role agent's session writes `loopd.signal.<session id>` to the plugin store when its
turn ends and sends one `loopd-signal:` line to the PM session, whose id the PM publishes
as `loopd.pm.<bundle>` at session start. Step 4 settles that session first; the line
orders the sweep and decides nothing. Absent companion ⇒ step 4 unchanged. Measured:
`turn.complete` is the end-of-work event in a `--bg` session, which never fires
`session.end` after its turn.

## Faster stamps (#365)

`resolve-model.sh --all` resolves every role in one process, and the stamp reads it once
instead of calling eight times. One fresh stamp: 0.96 s → 0.58 s; Python starts 22 → 6;
byte-identical output across nine scenarios. The stamp-heavy test harnesses fall with it.

## The status line says `loopd` (#362)

The one label the 3.3 rename missed, printed on every keystroke.

## The release question

*For each hook, gate and script, which assumption has this model generation made
unnecessary?* None. One assumption about **people** was found false: that an operator
will read a printed permission rule and edit a JSON file. The stamp asks instead.
