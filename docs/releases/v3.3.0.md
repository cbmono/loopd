# loopd 3.3.0

**Role agents are spawned in auto mode, and the bundle's own directory is renamed.** The
first ends `dispatch refused`: auto mode's classifier refuses a spawn that asks for
`bypassPermissions`, so a tick run in auto mode could not dispatch (nine refusals of ten in
one bundle, 2026-10-03 to -05). The second moves a bundle's state from `.ai-bridge/` to
`.loopd/` — and **it gives this upgrade an order** (below). Do the steps in that order.

**23 merged pull requests since 3.2.0.**

|---|---|

## Role agents run in auto mode (#333, #332)

Step 3 of the tick now spawns each role agent with `--permission-mode auto`, never
`bypassPermissions`. Measured on Claude Code 2.1.289: a detached session on Sonnet or Opus
holds auto mode, finishes a branch-commit-push task with no prompt, and has a force-push to
a default branch refused by the deny baseline. A bundle that had refused nine bypass spawns
accepted an auto one on the first try.

- **Haiku cannot hold auto mode** — the session is demoted to `default` and parks as
  `blocked`. Step 3 never spawns a role agent on an alias that resolves to Haiku; it
  resolves one tier up instead.
- **The refusal's remedy no longer says to leave auto mode.** It never should have.
- **The 3.2.0 note's claim that auto mode "is not an alternative today" was wrong** — it was
  measured on Haiku. That note carries its correction; so does the headless spike.

## The bundle directory is `.loopd` (#329)

`AB_DIR` flips to `.loopd`, and every spelled-out `.ai-bridge` under `plugin/` derives from
it. `migrate-bundle.sh` moves `.ai-bridge/` to `.loopd/` in one `git mv` — with its ignore
lines, the status-line pin and any knowledge mount's `core.worktree` — and commits. A
pre-3.0 bundle's root files are moved into the directory first, so the rename carries them.

## Faster gates and a faster stamp

- **A sibling's self-test verdict is reused while its bytes are unchanged** (#345).
  `required-checks.sh` ran two siblings' self-tests on every call, one of them 2–4 s. The
  verdict is keyed on the file's checksum and byte count and only a pass is recorded: an
  edited, truncated or swapped sibling is tested again, a failing one every time. Fail
  closed is unchanged.
- **`review-clearance.sh` execs 40 commands for a clearing call, not 154** (#342), about
  half the wall time. 501 recorded invocations are byte-identical before and after.
- **A bundle stamp spawns 93 fewer processes** (#343), 12% faster, byte-identical in six
  scenarios. The eight `resolve-model.sh` calls are the remaining 40% and are not touched.

  `continueAfterTasks` / `continueAfterDays`, absent ⇒ off.

## Tests and CI

- **The CI fast path is plugin-only again** (#335). 3.2.0 let a pull request that changed a
  script and its own harness skip the full suite (#324). Within hours one did, passed, and
  turned `main` red: about 40 harnesses read the plugin tree wholesale and name no file, so
  a path-derived selection cannot see them. Withdrawn, with the reason in `tests/run.sh`.
- **An `# iced` tier** (#346). The board is on hold, so its twelve harnesses leave the gate
  unless a changed path names them, and run in a nightly job. Live surfaces — the session
  banner, `AWAITING.md`, the status line — stay in the gate.
- **A time budget** (#346): every run prints its harness-seconds and five slowest; a full
  run over 3,600 is warned, never failed, because two runs of one tree measured 3,015 and
  4,108 on the CI runner.
- **`worktree-suite-parity` proves its property without re-running seven harnesses** (#341):
  229 s in CI before, 8 s locally after.
- **`review-clearance`'s harness is three files** (#342) — it had reached 538 s of a 600 s
  kill bound. Same 558 assertions, by name.
- **`main` was red four times in one day**, each time from two pull requests that were green
  alone (#328, #335, #340). Branch protection's `strict` flag is off, so nothing re-tests a
  pull request when its base moves. Not changed in this release; recorded.
- The brand guard pins each file's `.ai-bridge` count and sweeps `scripts/` (#337, #308).

## The release question

*For each hook, gate and script, which assumption has this model generation made
unnecessary?* One: that a role agent needs every permission check off to work unattended.
Auto mode on Sonnet and Opus does that work, so the bypass spawn and its grant rule are
retired. Nothing else was.
