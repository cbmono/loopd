# loopd 3.12.0

**The boards can now ask as well as show.** The served web board sends an answer or a new
project to a local queue that the next loop pass consumes, and the pane creates a project
one field at a time.

**2 merged pull requests since 3.11.0.**

| | |
|---|---|
| **Upgrading** | `/plugin update` (or `claude plugin update loopd-all`), restart Claude Code, then `/loopd:init` in each bundle so the queue file is gitignored |
| **Check it** | On `/loopd:board serve`, answer a question: the row reads Sent, and after the next `/loopd:dispatch` pass, Saved |
| **Breaking** | nothing. The published board is unchanged; only the locally served board can send |

## Web answers through a queue (#406)

- **Send answer and Start the project** on the served board POST to a local queue,
  guarded by a per-serve token and bound to 127.0.0.1 only. The next tick consumes the
  queue on its own, without the model reading the entries.
- **Sent, then Saved.** The page shows Sent when the entry is queued and Saved only after
  the loop has applied it. A replayed entry is never applied twice.
- **Nothing the page sends can promote or merge.** A project started from the board lands
  `draft` and gated and gets the bundle validator only; the owner reviews it at its draft.

## A project from the pane, field by field (#405)

- **The pane's New project** is a five-field form, target repo included, kept by a new
  deterministic `new-project-form.sh`. A missing field shows ✗ instead of stopping, and
  field text can never set kind, autonomy or repo.

## Known issues

From the adversarial review of #406, logged for a follow-up:

- The queue's `target_repo` accepts a relative path such as `../..`.
- A C1 control character in an answer can break the task document's YAML.
- A queue line with no valid id is dropped without a visible row.
- Answering a Q<n> the task does not have reads "already answered".
- The queue token is served regardless of the request's Host header.

## The release question

*For each hook, gate and script, which assumption has this model generation made
unnecessary?* None retired: the queue keeps the model out of the consume path on purpose,
so a page on localhost can deliver an answer but never act as the human.
