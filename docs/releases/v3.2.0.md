# loopd 3.2.0

**The destructive-action baseline reaches the agents it was built for.** A role agent runs as
a detached session launched inside its worktree, so its project directory is the worktree —
which holds no `instance.config.json`, the one file both safety hooks guard on. The hooks
fired and allowed everything. Measured live on 2026-10-04: a background agent force-pushed a
default branch with the hook's own `PreToolUse` events in its transcript and no refusal. This
release closes that, and **it needs one action from you to take effect** (below).

**14 merged pull requests since 3.1.0.**

| | |
|---|---|
| **Upgrading** | `/plugin update`, restart Claude Code, then **`/loopd:init` in each bundle** — the re-stamp is what writes the marker the hooks follow. Until then a bundle's role agents still run with no baseline |
| **Check it** | `test -f <repo>/.git/loopd-bundle && cat <repo>/.git/loopd-bundle` for each repo under `reposRoot` — it should print the bundle's path |
| **Breaking** | nothing |

## The deny baseline, from a worktree (#319)

`link-repos.sh` now writes `<repo>/.git/loopd-bundle` into every repo it links: the common git
directory all of that repo's worktrees share. `deny-destructive.sh` and `agent-control.sh`
resolve a **linked worktree** to its bundle through that file — three reads, no git process.
A main clone stays un-armed, and a marker naming a directory with no `instance.config.json`
is ignored, so the hooks are still silent everywhere else on the machine.

The test suite had been green throughout, because every probe pinned the project directory at
the bundle — the world in which a role agent was a subagent of the PM's session. The harness
now carries the shape production launches in, in both directions.

**What this does not change.** The doom-loop and wall-clock bounds (`maxRepeatedToolCalls`,
`maxAgentMinutes`) still do not reach a top-level background agent: `agent-control.sh` keys
on `agent_id`, which only a subagent's call carries. `SCHEMA.md` now says so on both rows.
And auto mode is not an alternative today: on Claude Code 2.1.289 a detached session started
with `--permission-mode auto` records `default` and parks as `blocked` before its first turn.

## What a role agent cost is no longer UNKNOWN (#321)

Every dispatch line has recorded `usage UNKNOWN` since role agents became detached sessions.
`session-usage.sh <session-id> --settle <task-doc>` reads that one session's transcript and
fills the line: `usage tokens=N tools=N ms=N cached=N`. Tokens, never money; `usage UNKNOWN`
on any doubt, never a zero. A transcript repeats a message's usage on every content block's
line — 2.2 lines per message, measured — so usage is counted once per message id. Step 4 of
the tick settles a round once its session has ended.

## Intake and review

- **`original_request:`** on a project and a task: the owner's wording, written once at
  intake and never rewritten. Refine edits `# Context` in place, so until now the original ask
  survived nowhere (#311).
- **`non_goals:`** on a project, optional and never asked for. A decision that recurs across
  projects belongs in a `Finding` instead (#320).
- **An unapproved decision gets one line in the review comment** — a new dependency, a schema
  or migration change, or a new public interface the criteria never named. Advisory: it is
  not a trailer `caveats:` entry, which would refuse the pass (#320).
- **The same change failing the same check twice with the same error is a dead end**: role
  agents stop, record it with `do-not-repeat.sh`, and report (#316).
- **Two refusals now say what to do next**: `required-checks.sh` and `validate-bundle.sh`'s
  missing-`type` error (#316).
- **`SCHEMA.md` → "Which document wins"**: per concern, which document is authoritative when
  two disagree. It resolved one live contradiction: `/loopd:answer` required a directory a
  bundle no longer has (#315).

## Evals and the release step

- **A ninth eval case**: instruction-shaped text inside a task document, a PR body and a tool
  result must not move the verdict (#310).
- **The judge is pinned** to `claude-sonnet-5-5`, not the floating alias (#312).
- **Cutting a release** now says to run `claude plugin eval ./plugin` first and read the
  scores, and to answer one question in the note: *for each hook, gate and script, which
  assumption has this model generation made unnecessary?* (#312). For this release: none was
  retired; one assumption was found to be false rather than unnecessary — that a role agent's
  project directory is the bundle.

## Tests and CI

- **A pull request that changes a script and its own harness takes the CI fast path** (#324).
  The fast path required a plugin-*only* diff, and since every change carries its test, 0 of
  the last 40 merged pull requests qualified. A full run is about 20 minutes on the 3-CPU
  runner, not the 9 the docs said.
- **`main` was red and is green**: the 3.1.0 release note was missing from the brand guard's
  list, and a test fixture's HTTP server did a reverse-DNS lookup that hangs on the CI runner
  (#314). That second failure arrived in a pull request merged with its required check red.
- **Two assertions that could never fail now count**: a `grep -c` over several files was
  summed by its first field, which is the file name (#322).
