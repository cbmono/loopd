# loopd 3.15.0

**The board serves itself, every role runs at a chosen reasoning effort, and the Needs-you queue is on by default.**
A session starting in a bundle starts the live board and the last one leaving stops it, the
effort each role spawns at is a config key beside its model tier, and `AWAITING.md` no longer
depends on when a bundle was first stamped.

**6 merged pull requests since 3.14.0** (#446–#451; 3.14.1 and 3.14.2 were patch bumps with no
note of their own).

## The board serves itself

- **`boardServe: true`** (seed default, tracked config, `board: false` implies off): SessionStart starts `board-serve.sh --detach` when nothing is serving, polls for the live state file and prints the served row; `GET /loopd/board` is the page (#450).
- **The server daemonises inside its own python** (`setsid` plus double fork, output to one log under the board directory), so the hook returns in under 3 s and never hangs on the pipe (#450).
- **Sessions are recorded**, one file per `session_id` holding the pid and start time of the nearest `claude` ancestor; a `compact` or `resume` overwrites its own record (#450).
- **One decider stops it**: SessionEnd removes its record and nudges the server; an auto-started server exits when no recorded session is alive after a grace period, checks every ~30 s, and so survives `/clear` and dies after a `kill -9` session; a reused pid with a mismatched start time is not counted alive (#450).
- **`boardPort` stays the per-machine key**; `normalise-config.sh` no longer moves it into the tracked file (#450).

## Reasoning effort per role

- **`roleEffort`** beside `roleTiers`, one entry per role: `medium` for the orchestration roles (project-manager, cataloguer, auditor), `low` for the explorer, `high` for the roles that write code or adjudicate (software-engineer, devops-engineer, qa-reviewer, plan-architect). Overridable per machine, local first, tracked second (#451).
- **`scripts/resolve-effort.sh <role>`** mirrors `resolve-model.sh`: prints the level or nothing, refuses an unknown level with one line, `--all` lists every role (#451).
- **Every spawn passes it**: `claude --bg … --effort <level>` for role sessions, `effort:` on every Agent-tool spawn of a map role; the `* DISPATCH` line records `· effort <level>` after the model, so a stall reads against the effort it ran at. `maxStallRounds` escalations are the evidence to move a role up (#451).
- **Measured, not assumed**: `claude --bg --agent` reads no frontmatter `effort:`, so a `--bg` session takes effort only from the map and otherwise runs at the machine's per-model setting (`modelSettings[<model>].effortLevel`), else the model default (#451).
- **Every plugin agent carries `effort:` in its frontmatter** equal to its seed value, and a test fails when the two disagree (#451).

## The Needs-you queue is on by default

- **`AWAITING.md` is created on any stamp that finds it missing**; `"awaiting": false` in the tracked config is the durable off switch, the `board` precedent. A bundle stamped before the queue existed gets one on its next `/loopd:init` instead of a `touch` instruction (#449).
- **One shared reader**: the tick, the banner, the status line and `/loopd:whats-up` all honour `awaiting: false` the same way (#449).

## Fixes and docs

- **The merge baseline treats a heredoc body as text**, so a Finding or commit message quoting the merge command passes while a body a shell runs is still refused (#446).
- **Docs sweep for the 3.14.0 review rules**, and a README "Larger teams" section: one bundle per person, one mounted knowledge repo (#447).

## Known issues

- `tests/mods.test.sh` pins zero warnings from `claude plugin validate --strict`, and Claude Code 2.1.310 prints an advisory block for any plugin whose `hooks.json` names a hooks module; the pin is being narrowed to exclude it.
