# loopd 3.13.0

**Briefs carry the knowledge base, and the boards and gates close the gaps 3.12 left open.**
Dispatch briefs now bring the task's own Service doc and a short list of current Findings,
stale KB docs are reported, and every known issue from the 3.12.0 note is fixed.

**20 merged pull requests since 3.12.0** (#413–#432; 3.12.1–3.12.4 were patch bumps with no
note of their own).

| | |
|---|---|
| **Upgrading** | `/plugin update` (or `claude plugin update loopd-all`), restart Claude Code, then `/loopd:init` in each bundle: the seed config gained `kbStaleCommits` (#423), and init reports any key your config lacks |
| **Check it** | `/loopd:whats-up` reprints the Needs-you block from `AWAITING.md`; a dispatch brief carries a `## Knowledge` section |
| **Breaking** | nothing for a human. An agent's `git push` that dodged `subagent_push_default` through a redirect, an option value or an explicit `HEAD` is now refused (#417, #425) |
| **Companions** | `loopd-yolo`, `loopd-mod-usage` and `loopd-all` 3.0.0 → 3.1.0, each because its shipped tree changed since its version was set (#430) |

## The knowledge base reaches the brief

- **Briefs match the task's own Service doc** and carry a seventh `## Knowledge` section of
  1–5 current Findings, recorded at dispatch for step 5's citation check (#418).
- **`kb-stale.sh` reports Service and Runbook docs whose code moved on** — `kbStaleCommits`
  (default 20) commits past their `timestamp:`. Report-only: the list rides in a cataloguer
  brief already going out (#423).
- **`build-kb-index.sh --check` counts untagged and off-enum Findings**, and both checkers cap
  a Finding at 40 body lines (#414).
- **`/loopd:kb-apply` may set `tags` or `archived` on human docs**, only with `--human-docs`
  naming exactly the report's set; agents are refused the flag by a hook rule (#420).

## Papercuts and the loop

- **`/loopd:whats-up`** reprints `AWAITING.md`'s rows as a numbered Needs-you block, with its
  refresh age and the tick-lock verdict (#424).
- **`deploy: manual`** (opt-in) records a merge as `merged, not deployed` with a `👉 do` row
  (#421); non-enum values fail validation and a task-level `manual` with no `target_repo` is
  written (#422).
- **`check-dispatch.sh` reports PRs from `branch:` that `pr:` omits** — still report-only (#416).
- **A papercut pass hands plugin-surface proposals upstream** to `.loopd/upstream-proposals.md`
  (#419).
- **`tick-lock.sh mint` prints UTC**, the seed names bundle-local scripts, and close-project's
  calls match their grants (#415).
- **An unrequested incremental review counts as round 2** — documented, with
  `mergeAtReviewCap` as the relief valve (#413).

## Gates and the interactive board

- **The merge gate admits exactly `loopd:project-manager`** and takes the repo from a PR URL
  (#431).
- **`subagent_push_default` is judged per push stage**, failing closed (#417), and stops
  reading redirects, option values and `HEAD`/`@` as the destination (#425).
- **The idle probe sees a reviewer's issue comment and role session state**, so a rate-limit
  reply or a stopped session is a delta, not an idle tick (#432).
- **`release-bump.sh` moves a changed companion** on a minor or patch bump (#430).
- **`board-serve.sh` embeds the queue token only for an allowed Host** (#427).
- **`web-queue.sh` refuses `.`/`..` repo segments and C1 controls**, and reports an id-less
  line instead of dropping it (#428).
- **`build-board.sh` survives a list- or object-valued `awaiting`** instead of blanking the
  board (#429).
- **The software-engineer drives headless Chrome** when a `--bg` session needs a browser
  picked and nobody can answer (#426).

## Known issues

From the 3.12.0 note, four of five are closed:

- Fixed: a relative `target_repo` (#428), C1 controls in an answer (#428), an id-less queue
  line (#428), the token served regardless of Host (#427).
- Not addressed in this release: answering a Q<n> the task does not have reads "already answered".

## The release question

*For each hook, gate and script, which assumption has this model generation made
unnecessary?* None retired: this release tightens gates (push rule, merge gate, Host check)
rather than relaxing them, and the KB additions are report-only.
