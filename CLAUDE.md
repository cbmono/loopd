# CLAUDE.md

Guidance for Claude Code when working in **this repo** — the ai-bridge template.

## What this repo is

A reusable **OKF control-panel template** for orchestrating background agents against a
group's product repositories. You stamp out one **instance** per group; each instance is
its own git repo under `~/workspace/<group>/_loopd-<group>/`.

- `plugin/` — **everything that ships**: the machinery, and (since task-022) the three files a stamp reads — `seed/`, `RETIRED` and a mirror of `VERSION`. An installed plugin is the CONTENTS of this directory, so anything `/loopd:init` needs that is not in here does not exist on a machine that never cloned this repo.
- `plugin/seed/` — starting content, copied into an instance **once, only if absent**. A change here reaches nothing automatically.
- `/loopd:init` — stamps out / refreshes an instance. `/loopd:welcome fix` — walks a pull's four cases and reports what's left for the human.
- `plugin/RETIRED` — seed paths the template has stopped shipping; reported, never deleted.
- `config/` — the ONE thing still outside the plugin, and the only reason to clone this repo: `init-bundle.sh --config` links three agent files into `${CLAUDE_CONFIG_DIR:-~/.claude}`. That is a per-machine decision, not a bundle one, and `plugin/` must never require it.
- `tests/` — bash harnesses. **There is a test suite and it must pass — in CI.** `.github/workflows/tests.yml` runs on every PR and push to `main` — everything on a push and on any PR whose diff leaves `plugin/` and the top-level harness files, the changed-path selection otherwise (0 of 40 merged PRs were plugin-*only*, because every change carries its test); `harness suite` is a **required check**, it tests the merge of your branch into the base, and it, not your machine, is the gate. **Locally, run only the harnesses your change touches** — `tests/run.sh --changed`, which is the selection CI itself takes (it runs `tests/run.sh --ci`; one implementation, no second copy in the workflow). `tests/run.sh --all` measured **39m 47s and 269.4k tokens** on 2026-08-29 against about 20 minutes (20m 10s, 2026-10-04) and no tokens for a full run in CI, so it is run once before the PR is opened, never polled, and a full run for any other reason is the exception (shared machinery every harness loads) that the PR body explains. See `plugin/seed/CONVENTIONS.md` → "The full suite belongs to CI". No build step, no lint.
- `docs/` — human-facing depth. `.claude/rules/` — the same prohibitions, path-scoped for agents.

**Keep machinery generic.** No org, repo, path, team or channel literals under `plugin/` —
those live in an instance's `instance.config.json` / `CLAUDE.md`.

**This repo is public.** Tracked placeholders must be verified unclaimed:
`example-user-007` / `example-user-008` (both 404 on github.com) and `example.com`
(RFC 2606). `alice`, `bob` and `jane-doe` are real accounts.

## Load-bearing invariants

**No count is given, deliberately** — the number drifted three times in one day. Every one
of these is a prohibition, and a prohibition has to be in context *before* you consider the
change it forbids. The reasoning behind each — what went wrong to produce it — is in
[`docs/conventions.md`](docs/conventions.md), numbered to match. Read that file before
editing the thing it governs; don't re-derive a decision it already records, and don't
shorten a "why" — relocate it intact.

- **Retiring machinery means deleting the file *and* letting `/loopd:init` sweep the links.** A dangling symlink into a vanished `plugin/` path still registers as a command and exits 127 as a hook, so absence here is **not** safe. Seed content is never swept — only reported, with the exact `rm`, via `RETIRED`. ([1](docs/conventions.md#1-retiring-content-is-asymmetric), [2](docs/conventions.md#2-retiring-machinery-means-deleting-the-file-and-letting-loopdinit-sweep-the-links))
- **`AWAITING.md` is the only status artifact and it is opt-in by presence.** There is deliberately no `/status` command and no full board — don't reintroduce either. Creation is gated on `FIRST_STAMP`; move it out of that guard and you break the off switch. `session-banner.sh` greps its heading and bullets **literally**. ([3](docs/conventions.md#3-awaitingmd-is-loopds-only-status-artifact-and-it-is-opt-in-by-presence))
- **A capability some deployments must not have is *one deletable file*, not a flag threaded through the machinery, and absence must mean the safe behaviour — never an error.** `plugin-yolo/companion/AUTONOMY.md` is the pattern, and it is now a whole separate **companion plugin** — core ships no capability file at all, so there is nothing for a stamp to re-link. A new one built as a file under `plugin/` would inherit the re-link hazard; build it as a companion instead (`plugin/README.md` → "Companion plugins"). ([4](docs/conventions.md#4-a-capability-some-deployments-must-not-have-should-be-one-deletable-file))
- **`build` and `research` projects are deliberately asymmetric — don't restore a question for symmetry.** `clis:` is written from an explicit flag or as an empty list; never a placeholder like `none`. ([5](docs/conventions.md#5-build-and-research-projects-are-deliberately-asymmetric))
- **The delegated merge gate resolves its required checks in `required-checks.sh`, and exit 0 is the only clearance.** Classify the platform probe on its **payload**, never its exit code; capture stdout and stderr separately. ([6](docs/conventions.md#6-the-delegated-merge-gate-resolves-its-required-checks-in-required-checkssh-and-exit-0-is-the-only-clearance))
- **A green check from a reviewer that declined to review is not verification.** `review-clearance.sh` asserts a review **artifact** exists. Take **evidence and pinning from the API** — a review's `state` and `commit_id` off `/repos/{o}/{r}/pulls/{n}/reviews` — and leave text matching exactly one job, **detecting a refusal**, where a false positive fails closed. Never pin by "the body mentions the head SHA": the refusal quotes that range too, at the PR's own head. **A review object that says nothing is not evidence on its own** — an empty `COMMENTED` is minted by the host for any inline reply, and no contentless object outranks a refusal at the same head. **The two body renderings must agree with the host on what a fence is** (≤3 spaces, never a tab or four), or an indented fence hides the refusal from the side that reads it. Unknown reviewer state is unverified, and so is a **missing PR-author login** — a field that is absent switches SCHEMA clause 8 off rather than failing. ([6](docs/conventions.md#6-the-delegated-merge-gate-resolves-its-required-checks-in-required-checkssh-and-exit-0-is-the-only-clearance))
- **Unknown reviewer state fails closed in the CALLER too — and `[ -x ]` is not "it runs".** A broken `review-clearance.sh` makes the gate silently disappear, so it must `--self-test` first, and the self-test must prove the file COMPLETE (a trailing sentinel), not merely that it starts. **A check's name never settles whether anybody looked** — ask for clearance on every PR instead of maintaining a table of vendor names, which cannot be finished. ([6](docs/conventions.md#6-the-delegated-merge-gate-resolves-its-required-checks-in-required-checkssh-and-exit-0-is-the-only-clearance))
- **`prune-worktrees.sh` is report-only. Do not reintroduce a delete, not even behind a flag.** Count commits, never compare to `origin/<default>`; a detached HEAD is never `REMOVABLE`; the mtime veto stays recursive. ([7](docs/conventions.md#7-prune-worktreessh-is-report-only-and-that-is-load-bearing))
- **`reclaim-worktree.sh` is the ONE thing that deletes a worktree, and it is not that flag** — the flag is forbidden because the pruner scans and infers; this reads one task's record and removes one path. Exit 0 needs `status: done` **and** every `pr:` URL MERGED: closed-unmerged, an empty `pr:` and an ignored file that is not a known cache are all refusals, and it passes no forced-removal flag. ([7](docs/conventions.md#7-prune-worktreessh-is-report-only-and-that-is-load-bearing))
- **`check-dispatch.sh` is report-only too, and for a sharper reason: it is what catches an agent that reported "done" with no PR open.** A checker that re-dispatched on its own reading would automate the most expensive failure a loop of this shape has. It asks only whether `status:` advanced, whether `pr:` names a URL and whether that pull request exists — never whether the work is any good, which is the reviewer's job — and it decides the parked verdict from the document alone, **before** `gh` is consulted, so an offline machine cannot silence it. ([plugin/seed/CONVENTIONS.md](plugin/seed/CONVENTIONS.md))
- **`validate-bundle.sh` was scoped by measuring first**, and validates only the schema-defined locations — a validator that buries 6 real errors under 77 warnings teaches people to ignore it. ([8](docs/conventions.md#8-validate-bundlesh-was-scoped-by-measuring-first-and-that-is-the-point))
- **`migrate-bundle.sh` fixes only what has one right answer, is report-only by default, and a false success is worse than the error it claims to fix.** The mapping list is closed; three refusals are the design; every write is verified after it lands. ([9](docs/conventions.md#9-migrate-bundlesh-fixes-only-what-has-one-right-answer-and-is-report-only-by-default))
- **The scaffold review is a three-stage chain with a declared fallback, never a skip** — validator, then an external reviewer, then `qa-reviewer` mode C. Every stage is advisory. ([10](docs/conventions.md#10-the-scaffold-review-is-a-three-stage-chain-with-a-declared-fallback-never-a-skip))
- **The cross-instance board keeps its off switch by being a *generated root file*, never machinery under `plugin/`**, and its **published-page field allowlist** — no question or blocker text, no document bodies, no author identity, no out-of-bundle paths — is a data-governance boundary you do not add to without reading the reasoning. A snapshot's **types** are untrusted too: one drifted instance must not blank the board for the rest. Its **three renderers** are presentation over that one contract — none re-derives from the bundle, escaping is per **medium** (a terminal's ESC and newline, not HTML's `<`), colour only on a TTY, and a **number is never truncated**. The watcher's resident-process cost is stated where a renderer is chosen. ([11](docs/conventions.md#11-the-cross-instance-board-is-a-writer-three-renderers-and-one-deletable-generated-file))
- **Three behaviours exist because a silent wrong answer is worse than a loud one.** `push-state.sh` must stay silent outside an instance yet **never emit a false zero** inside one, encoding every file-derived value to **one line** at its single awk choke point so a filename cannot forge the fence's markers — and never adding a second sanitising pass, which would mask that regression. An answered question is **moved, not deleted**, into a flat, not-machine-read `answered_questions:` list, with `open_questions` still the only promotion signal and no new validator check. `maxPrLoc` (**500** when absent) makes a role agent **propose** a split, never block a PR. ([12](docs/conventions.md#12-three-loopd-behaviours-that-all-exist-because-a-silent-wrong-answer-is-worse-than-a-loud-one))
- **An instance can be shared by two humans.** `owner` gates **dispatch** and never promotion; the tracked **`defaultOwner`** is what stops an *unowned* task being dispatched by both clones, and is the one config key deliberately **not** locally overridable; per-machine values live in a gitignored `instance.config.local.json` whose overridable set is listed in **one** place — `SCHEMA.md` → "Per-machine config overrides"; a tracked `people` map lets each clone author commits as its own human; and the derived `index.md` files (root and per-project, **never** `knowledge/index.md`) are gitignored. `/loopd:init` **asks** for that map on a first stamp — one batched prompt, guarded on `FIRST_STAMP` and on stdin being a TTY, never overwriting a value already there, writing nothing until it is confirmed, and parsing the result back before and after it lands. ([docs/sharing.md](docs/sharing.md))
- **`knowledge/references/` is the fifth knowledge kind**, promoted by adding the missing status enum rather than by relocating anyone's content — `knowledge/<kind>/` is a shape, not a list of names. ([14](docs/conventions.md#14-knowledgereferences-is-the-fifth-knowledge-kind))
- **An instruction addressed to an agent is executable only if that agent *holds* the tool — write for possession, never for what is installed.** A `tools:` allowlist is invisible from the prose it governs, so "dispatch `code-architect` **if it's installed**" read as satisfied for months while selecting a branch the agent could not run. For a **shared** doc the addressed agent is a **set** and the constraint is the **intersection**. Prefer **stating an absence** — name the missing tool *and* the route to take instead — over deleting the mention, which loses the reason and lets the clause come back; widening an allowlist is a standalone decision, never something a convenience clause settles. ([17](docs/conventions.md#17-an-instruction-addressed-to-an-agent-is-executable-only-if-that-agent-holds-the-tool))
- **The destructive-action baseline is a `PreToolUse` hook, not `permissions.deny` prefixes, and every rule is asserted in BOTH directions.** A prefix cannot see the condition that makes a command destructive (remote vs local host, repo root vs subdirectory, default vs feature branch), so as a prefix each rule is either too broad — and gets switched off, and a baseline nobody keeps protects nothing — or too narrow, which is **false comfort**, worse than an empty list. A hook can also be **proven**; a prefix pattern cannot be, from here. Keep `permissions.deny` to unconditional shapes only, each one duplicated by a hook rule so nothing depends on it, and never as a wildcard (`Bash(rm -rf /*)` refuses every absolute-path delete). The allow half of each test is the load-bearing half. Fail open on plumbing, never on a match. It stops named shapes, not every route — **credentials are the real boundary**. **It ships with the PLUGIN, alongside the kill switch** (`plugin/hooks/`, registered by `plugin/hooks/hooks.json`), so one install arms every instance on the machine instead of only the ones someone re-stamped — and because a plugin hook fires user-wide, both hooks **no-op SILENTLY** (no stdout, no stderr, no state) wherever `$CLAUDE_PROJECT_DIR/instance.config.json` is absent — **with one way back in: a linked worktree of a repo `link-repos.sh` has marked** resolves to its bundle through `<repo>/.git/loopd-bundle`. A role agent is a `claude --bg` session rooted IN its worktree, so without the marker the baseline fired and allowed everything it ran (a force-push to a default branch, measured live 2026-10-04) while every test pinned the project dir at the bundle; **a deny test must include the shape production launches in**, and a main clone (`.git` a directory) stays un-armed. The plugin/instance double-fire window during a migration is **accepted** and **no upgrade-lockstep machinery is added**: the roster append is dedup-guarded by agent id, so only the best-effort action log gains duplicate lines. ([19](docs/conventions.md#19-the-destructive-action-baseline-is-a-hook-and-it-is-narrow-on-purpose))
- **The target is one main thread, the PM dispatching freely, auto mode always on — and the plugin never writes a `claude --bg` grant or a workspace-trust key on any surface.** A plugin must not grant itself a bypass; `/loopd:init` prints a notice and the operator writes both (`tests/no-bg-grant.test.sh`). Role agents stay detached `claude --bg` sessions, never `Agent`-tool children, **spawned with `--permission-mode auto` and never `bypassPermissions`** — a spawn asking for a bypass agent is what auto mode's classifier refuses (nine refusals to one success in one bundle), and a `--bg` session on `sonnet` or `opus` holds auto mode and does the work unprompted (measured 2026-10-05). **Never on `haiku`**, where auto mode is unavailable and the agent parks. The spawn preflight stays permanent. ([docs/operations.md](docs/operations.md#the-supported-shape-one-main-thread-auto-mode-always-on))
- **The stable `plugins/loopd/bin` link is for the operator's terminal only, and the plugin never writes a shell rc.** `/loopd:init` re-points the link and prints the guarded `PATH` line; it never edits `~/.zshrc` and friends. Agents, `permissions.allow` rules and the seed's plugin-path recipe keep the absolute versioned path — never re-point them at `bin`, and never use a bare name: a permission rule matches the command text. (`tests/stable-bin-path.test.sh`, [docs/operations.md](docs/operations.md#a-stable-scripts-path-for-your-terminal-only))
- **A change to `core` carries NO version bump: the MERGER moves the number on `main`, right after the merge.** `core` is a closed list — `plugin/` (which carries `seed/`, `RETIRED` and the shipped `VERSION`), `plugin-yolo/`, `plugin-accounts/` and `plugin-llm/` (and any future companion plugin), `plugin-alias/` while the `ai-bridge` alias ships, `config/`, plus `install.sh` and `upgrade.sh` while the deprecation stubs still ship, i.e. the union of the two path-scoped rule files' globs — and everything else (`docs/`, `tests/`, `.claude/`, `.github/`, root `scripts/`) needs no bump at all. The number is **five files** — `VERSION`, `plugin/VERSION`, both manifests and the banner sample in `docs/operations.md` — and while every core PR carried them, any two open PRs conflicted on all five and had to land one at a time at a suite run each (five of six merges, 2026-09-06). So no PR edits them: merge, then run `plugin/scripts/release-bump.sh <major|minor|patch>` on `main` — the only writer of the five, which re-cuts the banner rule to match — and push that one commit straight to main, where the suite on push is the check. **Still not automatic**: no workflow bumps anything, and a human chooses the field. **No release process** follows from this: no changelog, no tags, no packaging, no publish. `plugin/scripts/check-template-version.sh` turns the number into the drift signal, and it speaks **only when behind** — equal, ahead, offline, unauthenticated or unparseable are all silence, because a false alarm trains the human to ignore the true one. ([20](docs/conventions.md#20-the-version-is-a-number-the-merge-moves-and-the-drift-check-speaks-only-when-behind))
- **The tool-allowlist check is pinned from both sides, because a closed list leaks in the one direction nobody can see: silence.** A tool missing from the vocabulary is **invisible**, not "prose" — the check passes, which is indistinguishable from there being nothing to find. So every tool an agent **grants** must be in the vocabulary, and any backticked **capitalised** name no classification rule recognises **fails** — single words included, because the grant guard can only ever see a tool something actually grants, never a hallucinated one; the 61 legitimate non-tool mentions are kept quiet **by rule** (OKF types derived from `SCHEMA.md`, an all-capitals shape, and a residual hand-list) rather than by a closed list. **The hand-list is not exempt from the same rule it enforces**: an entry must be **justified by a real mention** in `plugin/`, `.claude/` or `CLAUDE.md` or the build fails naming it — 9 of 11 speculatively pre-populated hook-event names had none and were as silent as the closed vocabulary this check replaced. The scanned set is **derived** from the docs agents are told to read, never a hardcoded list. A waiver's `(N)` budget is **not** what decides: a declared mention must **state the absence** *and* not be governed by a **directive verb**, since a reword holds a count constant and a possession cue alone was defeated 0-for-2 by ordinary prose. **`if` is not an absence cue**, because accepting it would bless the original defect. ([18](docs/conventions.md#18-the-tool-allowlist-check-is-pinned-from-both-sides-and-silence-is-a-failure))

- **`~/.claude` is owned by `cbmono/ai-setup`; this repo ships only what it probes for, and no drop-in directory is ever linked as a directory.** `config/required/` — the three agents the role agents `test -f` — is the entire set `init-bundle.sh --config` links, one **file** at a time (`agents/`, `commands/` and `skills/` are drop-in dirs, and a whole-dir link puts every drop-in inside this public repo). It was 21 more until a fork of ai-setup's tree left two installers claiming the same paths — 24 of ai-setup's 26 installable entries, 14 diverged; **never add a path back here — port the fix to ai-setup instead**, and `tests/config-ownership.test.sh` fails if you do. `plugin/` must never *require* `config/` — keep the probes and the bare `/loopd:init <dir>` interface — deleting `config/` must error nowhere, and `--config` never edits a real file: it does not ship or touch `settings.json`, and a symlinked parent directory is either already providing the file (reported, nothing written) or refused. ([docs/claude-config-ownership.md](docs/claude-config-ownership.md), [15](docs/conventions.md#15-the-config-layer-is-one-tier-and-the-arrow-stays-one-way))

## Conventions when editing

- **Test harnesses live in `tests/`, never under `plugin/`.** Everything under `plugin/` ships into every instance, and a fixture harness is not machinery an instance needs.
- **A `paths:` glob is only root-anchored with a leading slash.** Write `/plugin/**`, not `plugin/**` — a bare pattern matches that basename in any directory, and a trailing `/**` is not anchored either. The official docs say the opposite; `tests/rule-globs-anchored.test.sh` asserts it so the next reader can't "correct" it back.
- **Don't state a fallback in one doc only.** `worktreeRoot` (`<reposRoot>/_wt`), `maxPrLoc` (500), `maxPrFiles` (100), `maxAgentsInFlight` (4), `maxStallRounds` (2), `PUSH_STATE_MAX` (12), `watch-board.sh --interval` (2s), `WATCH_BOARD_WATCHER` (`auto`) and `continueAfterTasks`/`continueAfterDays` (absent ⇒ off, no default) are documented in files symlinked into instances whose config predates the key — every doc naming one must state it.
- **`docs/` is for humans; `CLAUDE.md` and `.claude/rules/` are for agents.** The story lives in `docs/` in exactly one place. Carry the rule here and point at the doc — don't duplicate the prose into both.
- **Addressing review feedback: fix, push, reply once — never ask for a re-review.** `.coderabbit.yaml` pins one review per PR. Only a rewrite that invalidates the original review justifies an explicit `@coderabbitai review`.
- **After adding or moving a skill or agent under `plugin/`, restart Claude Code and verify it registers** (no `skills:` prefix). New files aren't picked up mid-session, and a plugin the user has already installed needs `claude plugin update` before a new file exists on their machine at all.
- **Don't run `init-bundle.sh --config` from a git worktree.** Every symlink into `~/.claude` would point at a temporary checkout. It refuses, exits 2, and deliberately does **not** compute the main tree's path — every derivation is wrong once the git metadata lives apart from the working tree. Don't "improve" the message by deriving one. A **bundle stamp** is fine from a worktree: it writes no link into this repo.
- **No customer PII** in a task title, an answer, or a `Finding`. Titles reach the published board; answers persist for the life of the repo.
- **When two docs disagree, `plugin/seed/SCHEMA.md` → "Which document wins" says which one is wrong.** Fix the non-authoritative one so it restates and points; never ask. `tests/authority-table.test.sh` keeps the table truthful — every path it names resolves, and every agent, tick step and skill is under some row.

## Out of scope

- Don't add CI, a build step, or a `package.json`. This is markdown + bash.
- Don't vendor the machinery into an instance. It is symlinked from this checkout by design, so a clone on another machine has dangling machinery until `/loopd:init` runs there.
