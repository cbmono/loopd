# Machinery under `plugin/` (and under any companion plugin)

Loads when you read anything under `plugin/` or under a **companion** plugin's directory
(`plugin-yolo/`, `plugin-accounts/` and `plugin-llm/` today; the contract is in [`plugin/README.md`](../../plugin/README.md) →
"Companion plugins"). **Everything here ships to every machine
that installs the plugin** — one install per machine, not one stamp per bundle, so a
change reaches every bundle on that machine at the next `claude plugin update` with no
per-bundle step at all. There is no staging and no per-bundle review.

The reasoning behind each rule below is in [`docs/conventions.md`](../../docs/conventions.md),
numbered to match. Read the numbered section before changing the thing it governs; the
root [`CLAUDE.md`](../../CLAUDE.md) carries the same prohibitions always-loaded, because a
rule only fires on a **read** and a brand-new file matches nothing.

## Rules

- **Keep it generic.** No org, repo, path, team or channel literals. Those live in an instance's `instance.config.json` / `CLAUDE.md`.
- **Deleting a file here is not enough.** Already-stamped instances keep a symlink into the vanished path; a dangling command still registers and a dangling `SessionStart` hook exits 127 every launch. `/loopd:init` step 2b sweeps them — keep that sweep narrow (points into *this* template's `plugin/` **and** its target is gone). ([conventions 2](../../docs/conventions.md#2-retiring-machinery-means-deleting-the-file-and-letting-loopdinit-sweep-the-links))
- **A new deletable capability must not be a file here.** Machinery is re-linked unconditionally, so a per-instance `rm` comes back by itself. Put it in `plugin/seed/` (guarded like `AWAITING.md`) or make the disable a config key. Better still, build it as a **companion plugin** ([`plugin/README.md` → Companion plugins](../../plugin/README.md#companion-plugins)) — that is what `AUTONOMY.md` became, so core ships no capability file for a stamp to re-link. ([conventions 4](../../docs/conventions.md#4-a-capability-some-deployments-must-not-have-should-be-one-deletable-file))
- **`scripts/prune-worktrees.sh` never deletes.** Report-only, no flag. Count commits, never compare to `origin/<default>`; a detached HEAD is never `REMOVABLE`; the `PRUNE_ACTIVE_MINUTES` mtime veto stays recursive. ([conventions 7](../../docs/conventions.md#7-prune-worktreessh-is-report-only-and-that-is-load-bearing))
- **`scripts/reclaim-worktree.sh` is the one script that deletes a worktree — record-driven, one task path per call, no scan.** Exit 0 only on `status: done` **and** every `pr:` URL MERGED; closed-unmerged, an empty `pr:`, a detached HEAD, uncommitted or unpushed work, non-cache ignored content and a live process in the tree all refuse. No forced-removal flag, asserted at 0 hits. The mtime veto does **not** apply here — step 5 runs inside its window for every fast merge. ([conventions 7](../../docs/conventions.md#7-prune-worktreessh-is-report-only-and-that-is-load-bearing))
- **`scripts/required-checks.sh`: exit 0 is the only clearance.** Classify the platform probe on its **payload**, never `gh`'s exit code, and capture stdout and stderr **separately**. Three answers only — JSON, the literal "no required checks" message, anything else ⇒ exit 2. ([conventions 6](../../docs/conventions.md#6-the-delegated-merge-gate-resolves-its-required-checks-in-required-checkssh-and-exit-0-is-the-only-clearance))
- **`scripts/review-clearance.sh` asks the MERGE question first: `mergeable`/`mergeStateStatus` at the head, before any artifact is read.** CONFLICTING/DIRTY is **exit 7** — a rebase round, never a merge row, never a review request; UNKNOWN is **exit 2**, a hold, because the host computes it lazily and answers UNKNOWN for seconds after the base moves. Re-read **every** tick: it changes when the default branch moves with no commit on the PR, which is how three PRs read "merge — verified, CLEAN" on 2026-09-13 while GitHub called them all DIRTY. `review-rounds.sh` opts out with `--no-merge-check` — it asks about the past, and a new code in its fatal `*` arm would turn "this PR conflicts" into "the round count is unknown". ([conventions 6](../../docs/conventions.md#6-the-delegated-merge-gate-resolves-its-required-checks-in-required-checkssh-and-exit-0-is-the-only-clearance))
- **`scripts/review-clearance.sh`: a review ARTIFACT, never a check conclusion — and exit 0 is the only clearance.** Evidence and pinning come from the **API** (a review's `state` and `commit_id`); text matching only ever detects a **refusal**, where a false positive fails closed. Never pin by the `between <base> and <head>` range (the refusal quotes it too, at the PR's own head — that is the trap). Classify the refusal first, consider clearance only for what survives. Every vendor fact stays in the tables, and a missing or wrong row costs a refusal, never a clearance. ([conventions 6](../../docs/conventions.md#6-the-delegated-merge-gate-resolves-its-required-checks-in-required-checkssh-and-exit-0-is-the-only-clearance))
- **The caller fails closed on FOUR edges, not one.** `required-checks.sh` makes the sibling **prove it runs** (`--self-test`) — `[ -x ]` is a mode bit, and a broken sibling makes every check look like CI and the gate vanish. A check named for a reviewer no row owns is **unknown (exit 2), not CI**. Each reviewer-owned name clears via `--for-check`, so one vendor cannot clear another's. **Unbalanced fences hand back the raw body**; a toggle with no END check is a one-character bypass. ([conventions 6](../../docs/conventions.md#6-the-delegated-merge-gate-resolves-its-required-checks-in-required-checkssh-and-exit-0-is-the-only-clearance))
- **`scripts/review-rounds.sh` counts rounds; it never re-decides what a review is.** Candidate commits come only from the **host** (the PR's commit list, and the `commit_id` on a review object) — never from a SHA an artifact's body mentions, because the recorded refusal mentions one. Whether a candidate counts is `review-clearance.sh`'s answer, obtained by replaying that file **unmodified** once per candidate against one fetched snapshot; do not re-implement its tables, its renderers or its refusal tiers here, and do not relax it. A round is a distinct **commit**, not an artifact (one review run leaves two). The cap is **hard** — no `--cap` flag. **The count is a floor and must stay one:** a comment-only (route C) round is pinned by the commit its body names, so an orphaned commit or the vendor's edited summary comment loses it — measured on #34, the REST timeline publishes nothing that recovers it. Do **not** close that by adding body-mentioned SHAs as candidates: every review comment also names the PR's **base**, which turns #29 from one round into two. One low costs one dispatch; one high is a phantom round anyone can write. And **exit 0 is not clearance**: this script has no part in the merge gate, which is why it may mask SCHEMA.md clause 8 for the fallback-verifier runs and `review-clearance.sh` may not. ([plugin/seed/CONVENTIONS.md](../../plugin/seed/CONVENTIONS.md))
- **`scripts/validate-bundle.sh` checks only the schema-defined locations.** Don't extend it to `index.md`, `log.md`, `sources/` or `deliverables/`; don't add an `owner` or `answered_questions` check. ([conventions 8](../../docs/conventions.md#8-validate-bundlesh-was-scoped-by-measuring-first-and-that-is-the-point))
- **`scripts/migrate-bundle.sh`: the mapping list is closed, the three refusals are the design, and every write is verified after it lands.** A silent no-op that reports `FIXED` is the bug class this script already shipped once. ([conventions 9](../../docs/conventions.md#9-migrate-bundlesh-fixes-only-what-has-one-right-answer-and-is-report-only-by-default))
- **`scripts/write-snapshot.sh` / `scripts/build-board.sh` / `scripts/print-board.sh` / `scripts/watch-board.sh`:** the snapshot's field list is a **data-governance boundary** — read `_sensitivity` before adding a key. Every number goes through `toint()`; never a bare `int()` on snapshot data. No GNU-only regex escapes in the writer. A renderer reads the **snapshot**, never the bundle, and escapes for **its own medium** — the terminal board strips Unicode category C, colours only a TTY, and never clips a number. `watch-board.sh` reuses `build-board.sh` rather than forking the HTML, refreshes only **this** instance's snapshot, and probes `fswatch` before using it. ([conventions 11](../../docs/conventions.md#11-the-cross-instance-board-is-a-writer-three-renderers-and-one-deletable-generated-file))
- **`scripts/close-project-folder.sh` prunes by four explicit paths, and is report-only without `--apply`.** `tmp/`/`temp/` directories, `.DS_Store`, and non-markdown files under `sources/` — never `deliverables/` (it holds .pdf/.html/.png output), never `tasks/`, never `sources/**/*.md` (`index.md` cites them), and **never a repo-wide extension sweep**. A declared `artifacts:` path is a keep-set the prune cannot cross. `tmp/` is reported by path and entry COUNT, never by filename — on the project this rule came from it held employee records, and a filename is content. ([SCHEMA.md](../../plugin/seed/SCHEMA.md) → "Project & objective completion")
- **`scripts/task-owner.sh` resolves *and* compares — two operations, not one chain.** `ownerGithubUser` answers "who is this clone?" and is never a source of ownership. Exit 0 is the only clearance. It gates **dispatch**, never promotion. ([docs/sharing.md](../../docs/sharing.md))
- **`scripts/check-dispatch.sh` is report-only, and asks one dumb question.** Did `status:` advance, does `pr:` name a URL, does that pull request exist — nothing about whether the work is any good (that is the reviewer's job). It must never re-dispatch, never write to the task document, and never ask the host for anything but a read; re-running an already-finished task sequence is the most expensive failure this loop has, and a checker that acted on its own reading would automate it. Exit 0 is the only clearance, and the parked verdict (exit 1) is decided from the document **before** `gh` is consulted, so an offline machine cannot silence it. ([plugin/seed/CONVENTIONS.md](../../plugin/seed/CONVENTIONS.md))
- **`.claude/hooks/push-state.sh` must never emit a false zero**, must stay silent outside an instance root, and encodes every file-derived value to one line at its **single** awk choke point. Do not add a second sanitising pass — it would mask the regression the test watches for. ([conventions 12](../../docs/conventions.md#12-three-loopd-behaviours-that-all-exist-because-a-silent-wrong-answer-is-worse-than-a-loud-one))
- **`.claude/hooks/session-banner.sh` greps `AWAITING.md` literally** (the `## 🔴 Awaiting you` heading, asterisk-space bullets). The `project-manager` agent owns that exact layout; reshaping either silently empties the startup nudge. Both hooks fence their output as **untrusted data** — keep the boundary. Its **three renderings are one buffer**: `--format json` for the SessionStart channel (SGR renders there, markdown arrives literal), `--format md` for the path `/loopd:welcome` relays (markdown renders, 0 of 4 ANSI escape bytes survive), plain text for a terminal — and `NO_COLOR` reaches all three, because on a channel that draws `**bold**` as bold, emphasis *is* the colour. **A fixed-width table relayed as markdown may contain only characters markdown leaves alone**, so every value out of a config file or `VERSION` passes `cell` at the one choke point every row goes through (`add`), and the owner row is spelled `user · address` rather than escaped — an escape is itself a character, and the SessionStart channel renders no markdown, so it would print the backslash. Widths are measured with `nchars`, never `${#s}`: that counts BYTES in a C locale, where every `TIER→MODEL` row came out two columns short of its own header. ([conventions 3](../../docs/conventions.md#3-awaitingmd-is-loopds-only-status-artifact-and-it-is-opt-in-by-presence))
- **`.claude/commands/new-project.md`: `build` and `research` are asymmetric on purpose.** Don't restore a question for symmetry. `clis:` comes from an explicit flag or is an empty list — never a placeholder. Step 8's review chain has a **declared fallback, never a skip**. ([conventions 5](../../docs/conventions.md#5-build-and-research-projects-are-deliberately-asymmetric), [10](../../docs/conventions.md#10-the-scaffold-review-is-a-three-stage-chain-with-a-declared-fallback-never-a-skip))
- **`SCHEMA.md` is the normative contract** for document types, the verification predicate and the per-machine override set. `docs/schema.md` is orientation only and must not restate a field list. Adding a knowledge kind means declaring its status enum — the location filter is a shape, not a list of names. ([conventions 14](../../docs/conventions.md#14-knowledgereferences-is-the-fifth-knowledge-kind))
- **`.claude/agents/*`, `CONVENTIONS.md`, `SCHEMA.md`, `AUTONOMY.md`: an instruction is executable only if the addressed agent *holds* the tool.** Never condition on what is **installed** — "dispatch `code-architect` if it's installed" reads as satisfied while selecting a branch the agent cannot run. For a doc read by several agents the constraint is the **intersection** of their `tools:` lists. Naming an absent tool is often right: **state the absence and give the route**, declared with a budget *and* a reason (`<!-- tool-mention: Workflow(1) — why -->`). The count is not what clears it — the mention itself must say a reader may not hold it **and must not read as an instruction to use it**. And a tool granted to any agent must also be in the checker's vocabulary, or the checker cannot see it; any other backticked capitalised name must be classifiable, or it fails — including via the residual hand-list, whose own entries must each be justified by a real mention in the tree or the build fails naming the unused one. ([conventions 17](../../docs/conventions.md#17-an-instruction-addressed-to-an-agent-is-executable-only-if-that-agent-holds-the-tool), [18](../../docs/conventions.md#18-the-tool-allowlist-check-is-pinned-from-both-sides-and-silence-is-a-failure))
- **State every fallback, every time.** These docs are read inside instances whose config predates the key: `worktreeRoot` → `<reposRoot>/_wt`, `maxPrLoc` → 500, `maxAgentsInFlight` → 4, `PUSH_STATE_MAX` → 12, `boardInstances` absent → just this instance, `watch-board.sh --interval` → 2s, `WATCH_BOARD_WATCHER` → `auto`.
- **`scripts/ai-bridge.sh` reports facts that can be false, and `fix` dispatches on the tier each row of its ONE list declares.** Never add a rules recital — a line that reads the same on a healthy instance and a broken one does not belong there, and *"always use the dispatch loop"* contradicts `plugin/seed/CLAUDE.md` outright. Never add a second list: `check`, `fix`, `--list` and the banner filter all read `CHECKS`, and the hook carries the name of no individual check. **Never add `fix_config_uncommitted` or `fix_tick_lock`** — uncommitted config is a QUESTION (a `maxPrLoc` value can be a decision minutes old) and `tick-lock.sh release` is the human's override (a long tick is not a dead one); the script refuses to run at all if either appears, and `tests/ai-bridge-command.test.sh` asserts the non-action against a real modified config and a real stale lock. The bare form **`exec`s** `session-banner.sh` and must stay byte-identical to it — in the RENDERING it asked the hook for: with no arguments and a piped stdout it asks for `--format md`, because that path is relayed as markdown and ANSI does not survive it, and any argument at all leaves the choice to the caller. **It also asks for `--no-logo` on both no-argument branches**: the ship renders on the SessionStart channel alone, because a relayed copy drops the leading space of its first line and carries no colour. ([conventions 21](../../docs/conventions.md#21-loopdwelcome-reports-facts-that-can-be-false-and-fix-is-tiered-in-code))
- **The two enforcement hooks are PLUGIN files now, not machinery — `plugin/hooks/deny-destructive.sh` and `plugin/hooks/agent-control.sh`.** They are named here because `plugin/seed/.claude/settings.json` no longer registers them and a reader editing that file needs to know where they went: registration is `plugin/hooks/hooks.json`, delivery is `/plugin install loopd@loopd`, and neither is stamped by `/loopd:init`. Both open with the **instance-root guard** — resolve `CLAUDE_PROJECT_DIR` (never the payload `cwd`), exit 0 in complete silence unless `instance.config.json` is there — because a plugin hook fires in every session on the machine. `permissions.deny` stays in `settings.json`: a plugin manifest has no field to carry it. ([conventions 19](../../docs/conventions.md#19-the-destructive-action-baseline-is-a-hook-and-it-is-narrow-on-purpose), [16](../../docs/conventions.md#16-the-kill-switch-is-one-hook-and-it-fails-open))
- **`plugin/hooks/deny-destructive.sh` is the destructive-action baseline, and its rules stay NARROW.** Each rule must be one no instance wants to remove — the escape hatch is a human running the command in their own terminal, which is what makes narrowness affordable. Add a rule as `rule_<name>()` + a word in `RULES` + **both directions** in `tests/deny-baseline.test.sh`; the allow half is the load-bearing one, since a rule that catches legitimate work gets the whole baseline switched off. Keep `permissions.deny` to unconditional shapes only, each duplicated by a hook rule, and never as a wildcard. Fail open on plumbing (no `jq`, bad payload), never on a match; a refusal is JSON on stdout and the exit status is always 0. ([conventions 19](../../docs/conventions.md#19-the-destructive-action-baseline-is-a-hook-and-it-is-narrow-on-purpose))
- **A change here carries NO version bump — the merger moves the number on `main` afterwards.** This directory is `core`, and it now CONTAINS `seed/`, `RETIRED` and the shipped `VERSION` (with `/config/`, `/loopd:init`, `/loopd:welcome fix`), and core is what a version exists to track: a **new** file here reaches an already-stamped instance only when `/loopd:init` runs again, which is the drift the number makes visible. **Leave `VERSION`, `plugin/VERSION`, both manifests and the banner sample alone** — they are five files a second open PR also wants, which is what used to force core PRs to merge one at a time. After the merge the human runs `plugin/scripts/release-bump.sh <major|minor|patch>` on `main`, the only writer of the five, and pushes that commit. One source: a doc that *displays* the number is asserted against `VERSION` by `tests/template-version.test.sh`. No changelog, no tags, no packaging — there is no release process here and adding one is out of scope. ([conventions 20](../../docs/conventions.md#20-the-version-is-a-number-the-merge-moves-and-the-drift-check-speaks-only-when-behind))
- **Test harnesses never live here.** They go in `/tests/` — a fixture harness is not machinery an instance needs.
