# The installer, the seed refresher, and `plugin/seed/`

Loads when you read `init-bundle.sh`, `refresh-seeds.sh`, `RETIRED`, or anything under
`plugin/seed/`. **`install.sh` and `upgrade.sh` at the root are one-screen deprecation
stubs** that print the `/loopd:init` line and exit 2; they ship for one version and are
then deleted. `/loopd:init` and `/loopd:welcome fix` are the working replacements
they point at. The engines are `plugin/scripts/init-bundle.sh` and
`plugin/scripts/refresh-seeds.sh`, and they run from the plugin so a bundle needs no clone
of this repo at all.
Reasoning: [`docs/conventions.md`](../../docs/conventions.md) and
[`docs/operations.md`](../../docs/operations.md).

## Rules

- **`init-bundle.sh` only seeds-if-absent, converts a symlink-era bundle, and links `repos/`. It never removes bundle content.** That is the safety property that makes it safe to run blindly on a repo full of somebody's work — don't spend it to save an `rm`. ([conventions 1](../../docs/conventions.md#1-retiring-content-is-asymmetric))
- **Retired *seed* paths are declared in `RETIRED` and reported with the exact `rm`, never deleted.** Add the entry in the same commit that deletes the seed file, and **never prune the manifest** — an instance stamped years ago still has the file. Absence, an empty file, a comment, a blank line, or a path an instance doesn't have are all silence, never an error. ([conventions 1](../../docs/conventions.md#1-retiring-content-is-asymmetric))
- **The conversion sweep is decided structurally, never by name:** a symlink outside `repos/` is removed when it is dangling, when its target contains `/symlink/`, or when its target resolves inside a template checkout. Anything else — a real file, a link of the human's own that resolves elsewhere — is reported and left. A closed list of paths would be wrong for exactly the oldest bundles, which are the ones that most need converting. A real file, a link elsewhere, or a link that still resolves is left alone. ([conventions 2](../../docs/conventions.md#2-retiring-machinery-means-deleting-the-file-and-letting-loopdinit-sweep-the-links))
- **`FIRST_STAMP` is the off switch for `AWAITING.md` and `SNAPSHOT.json`.** Both are created on the first stamp **only**, and it is computed *before* seeding. Move creation out of that guard and `rm` stops working. A second clone of a shared bundle is **not** a first stamp — say so, with the `touch`. ([conventions 3](../../docs/conventions.md#3-awaitingmd-is-loopds-only-status-artifact-and-it-is-opt-in-by-presence), [11](../../docs/conventions.md#11-the-cross-instance-board-is-a-writer-three-renderers-and-one-deletable-generated-file))
- **A `.gitignore` line is inert for a file git already tracks.** Append the line and then *report* the exact `git rm --cached`; never untrack anything yourself. ([docs/sharing.md](../../docs/sharing.md))
- **The derived-index ignore lines must NOT go in `plugin/seed/.gitignore`.** That file is an active `.gitignore` over this template's own `plugin/seed/` directory, so a `/index.md` line there matches `plugin/seed/index.md` and silently stops this repo tracking its own seed file. `tests/derived-indexes.test.sh` holds the trap closed. ([docs/sharing.md](../../docs/sharing.md))
- **Refuse to run from a git worktree, exit 2, before any write** — and do **not** compute the main checkout's path. Both obvious derivations are wrong once the git metadata lives apart from the working tree; name `git worktree list` instead. `tests/installer-worktree-guard.test.sh` asserts both directions and that no path is printed.
- **`/loopd:welcome fix` is report-only by default**, samples `AUTONOMY.md`'s presence *before* calling `/loopd:init`, and ends with a numbered "what's left for you" list — that list is what a collaborator actually reads. Its `CONFLICT` and `UNKNOWN` verdicts **never** write. ([conventions 4](../../docs/conventions.md#4-a-capability-some-deployments-must-not-have-should-be-one-deletable-file), [operations 1](../../docs/operations.md#1-installing-and-upgrading-two-halves-and-neither-updates-the-other))
- **Order inside `/loopd:welcome fix` is fixed:** `/loopd:init` → `validate-bundle.sh` → `migrate-bundle.sh` → seed judgement. The validator ships instantly through its symlink and reports errors nothing repairs until the migration runs.
- **`plugin/seed/` placeholders must be verified unclaimed.** This repo is public: `example-user-007` / `example-user-008` (both 404) and `example.com` (RFC 2606). `alice`, `bob` and `jane-doe` are real accounts. `tests/commit-as-identity.test.sh` asserts it. ([docs/sharing.md](../../docs/sharing.md))
- **`--config`'s sweep is the handover mechanism, so treat it as one.** Retiring 21 paths on every existing machine is not a tidiness pass: (i) the sweep roots come from the fixed `CONFIG_MANAGED_TOPS`, never from what `config/` still contains, or a directory whose last file went stops being searched; (ii) the roots are an **array** — `find $roots` unquoted, with an `SC2086` disable hiding it, silently skipped every subdirectory when `CLAUDE_CONFIG_DIR` held a space (21 retired/0 dangling without one, 2/19 with); (iii) when it retires anything it **names `cbmono/ai-setup`**, because a user is otherwise told what vanished and not where it went; (iv) it retires what is MISSING from the discovered source list, so it must never act on a list it could not fully build — `config_entries` discards both the `cd` and the `find` status by construction, and a source directory that is unreadable but executable makes `find . -type f` exit **0** with no output, which read as *retire everything* (measured: exit 0, every link gone including the ones still shipped, no warning, one mode silent on stderr). Two refusals hold it, and **neither subsumes the other**: the discovery probe fires on an INCOMPLETE list even when non-empty (one unreadable subdirectory among several), and the sweep refuses when discovery returned **nothing while links into `config/` still exist** and a tier directory is still present — a tier that is *gone* is what keeps `rm -rf config/required` retiring correctly. Do not "simplify" either into a status check; there is no non-zero status to catch.
- **In the config half, every write is checked and a failure returns non-zero.** `set -e` cannot help here: the sole caller is `config_install || config_rc=$?`, which suspends errexit for the whole function, so an unchecked `ln -s`/`mv`/`mkdir -p` printed `Done. 3 linked` and exited 0 having linked nothing. The consumers are `test -f` probes, so a false count is invisible for the rest of the session.
- **`--config` links per FILE, never a directory.** `agents/`, `commands/` and `skills/` are drop-in directories; a whole-dir link aims them at this checkout, so anything an installer drops there lands in a public repo. Don't "simplify" it, and don't add a gitignore allow-list to compensate for a link shape you can simply avoid. ([conventions 15](../../docs/conventions.md#15-the-config-layer-is-one-tier-and-the-arrow-stays-one-way))
- **`config/` ships exactly what `plugin/` probes for — three agents — and nothing else.** `~/.claude` is owned by [`cbmono/ai-setup`](https://github.com/cbmono/ai-setup); this layer exists only so a fresh laptop satisfies the `test -f` probes without cloning a second repo. It used to be a fork of ai-setup's whole tree, which put 24 paths under two installers with 14 diverged and two secret-exposure fixes stranded in the private copy. **A command, hook or skill you want on a new machine is an ai-setup install, never a file added back here** — `tests/config-ownership.test.sh` derives the allowed set from the probes and fails on anything else. Deleting `config/` must break nothing and error nowhere. ([ownership](../../docs/claude-config-ownership.md), [conventions 15](../../docs/conventions.md#15-the-config-layer-is-one-tier-and-the-arrow-stays-one-way))
- **`plugin/` must never require `config/`.** Keep the `test -f ~/.claude/agents/…` probes exactly as they are: a stamp on a machine that never ran `--config` has to work. And keep the bare `/loopd:init <dir>` interface — three live instances and `/loopd:welcome fix` call it that way, so `--instance` is only its explicit spelling. ([conventions 15](../../docs/conventions.md#15-the-config-layer-is-one-tier-and-the-arrow-stays-one-way))
- **`--config` never edits a real file, and never writes THROUGH a symlinked directory.** It does not ship a `settings.json` and does not touch one — that file is ai-setup's, and it can hold permissions a human tuned by hand. ai-setup links `~/.claude/agents` as a whole directory, so a symlinked parent is the normal case, not an error: when the entry already resolves through it the requirement is met, so it is reported and nothing is written; when it does not resolve it is refused with the `mv` that fixes it. That is what makes the two installers compose in either order. Every write it makes is a symlink it created itself. ([ownership](../../docs/claude-config-ownership.md), [conventions 15](../../docs/conventions.md#15-the-config-layer-is-one-tier-and-the-arrow-stays-one-way))
- **The session defaults are INLINED in `plugin/seed/CLAUDE.md`** — don't turn them back into an `@import`. The old `@~/.claude/claude-defaults.md` line resolved to nothing on a machine that never installed the parent repo, silently, in every instance. The stale-import nudge is report-only and its grep is line-anchored, because the replacement section quotes the old line to explain itself. ([conventions 15](../../docs/conventions.md#15-the-config-layer-is-one-tier-and-the-arrow-stays-one-way))
- **`init-bundle.sh` ASKS for the `people` map on a first stamp, and the three guards are the deliverable:** only on `FIRST_STAMP`, only when stdin is a TTY (otherwise skip and print the instruction), and never overwrite a value already there — checked against the FILE, not inferred from `FIRST_STAMP`. One batched prompt, and **nothing is written until a separate confirmation**, so an interrupt or an EOF cannot leave a map that resolves for one human and falls through for the other. The write is parsed back before and after it lands, and with no `jq`/`python3` on the machine the prompt is not offered at all. Don't ask serially, and don't add a value the human did not type. ([docs/sharing.md](../../docs/sharing.md), `tests/team-setup.test.sh`)
- **`init-bundle.sh` ASKS before writing the `claude --bg` spawn grant, and only at a terminal.** Enter is yes (owner, 2026-10-09: "let loopd:init ask during installation with Y as default"); `n` prints the rule; a stamp with no terminal writes nothing and prints the rule, and `--spawn-grant` is the human's yes relayed by `/loopd:init`. The stale shapes — a bare `Bash(claude --bg *)`, a `bypassPermissions` spawn, a retired agent namespace — are named with why and replaced on that same yes, never silently. An existing rule is never duplicated, a file that does not parse is never rewritten, and a trust key is never written by anything here. Both halves: `tests/no-bg-grant.test.sh`. ([operations → the supported shape](../../docs/operations.md#the-supported-shape-one-main-thread-auto-mode-always-on))
- **A `knowledge` key means step 1 seeds NOTHING under `knowledge/` and step 8 mounts it.** The nine placeholders a stamp used to write there made `kb-sync.sh mount` refuse ("already a real folder") and point at `kb-migrate.sh` — blank seeds one `--apply` away from the company's knowledge repo (measured 2026-10-09, second clone). A `knowledge/` with real content is still refused in kb-sync's own words; one holding only the seed's placeholders is named with the exact `rm` and never removed; a mount whose fetch failed is named with `kb-sync.sh pull`, and a stamp never fails on the network. (`tests/kb-mount.test.sh`)
- **The ONE key step 4c fills into an EXISTING `instance.config.local.json` is `authorEmail`** — from `people[ownerGithubUser]` or `--email`, read back before and after it lands. Every other key in an existing file is reported, never written. (`tests/init-local-config.test.sh`)
- **A change here carries NO version bump — the merger moves the number on `main` afterwards.** These paths are `core`, and so is `/plugin/` — the closed list is `plugin/` (which carries `seed/`, `RETIRED` and the shipped `VERSION`), `config/`, `/loopd:init` and `/loopd:welcome fix`, the union of this rule's globs and `machinery.md`'s. Core is what a version exists to track: a **new** file under `plugin/` reaches an already-stamped instance only when `/loopd:init` runs again, and `plugin/seed/` content is copied **once, ever** — that is the drift the number makes visible. **Leave `VERSION`, `plugin/VERSION`, both manifests and the banner sample alone**: they are five files every other open core PR also wants, which is what used to force those PRs to merge one at a time. After the merge the human runs `plugin/scripts/release-bump.sh <major|minor|patch>` on `main`, the only writer of the five, and pushes that commit. One source: the two copies are asserted byte-equal, and a doc that *displays* the number is asserted against `VERSION`, both by `tests/template-version.test.sh`. No changelog, no tags, no packaging — there is no release process here and adding one is out of scope. ([conventions 20](../../docs/conventions.md#20-the-version-is-a-number-the-merge-moves-and-the-drift-check-speaks-only-when-behind))
